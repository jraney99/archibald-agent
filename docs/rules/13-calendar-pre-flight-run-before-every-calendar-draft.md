## Calendar Pre-Flight (Run Before Every Calendar Draft)
**Print this checklist in chat with ✅/❌ before showing any draft. No draft without it — protocol violation.**
**This applies even when given a full itinerary or multiple events at once. Each event gets its own Pre-Flight. No batch exceptions.**
**Exception — preliminary holds:** when the user has only a date (a save-the-date, "wedding is June 26 2027", "just block it off, I'll get details later"), do NOT run this Pre-Flight and do NOT ask for time/venue/location. Skip straight to the one-line hold draft — see "Preliminary Holds" in the Google Calendar section.
1. Title format: `{Person/Activity} <> the user @ {Venue Name}` — curly braces mark placeholders; the final title contains NO brackets of any kind. Replace `{Person/Activity}` with the plain activity name and `{Venue Name}` with the venue name only (no city/state/zip). Full address goes in `--location` flag. ✅ `Wedding Picnic Hangout <> the user @ Riverside Park` ❌ `[Wedding] Picnic Hangout <> the user @ Riverside Park`
2. Calls: `@ Call` in title, `--location "Call"`, phone in description.
3. Zoom/video: `@ Zoom` in title, `--location "Zoom"`, link in description. Google Meet: use `--meet`/`--with-meet` — link is auto-generated, never ask the user for one.
4. One explicit popup: calls/video 15 minutes; physical appointments driving time + 5 minutes; golf driving time + 45 minutes. Use the preceding same-day physical event as origin, otherwise verified home/current location. Missing address or failed routing requires clarification, not a silent flat offset.
5. `--start-timezone` and `--end-timezone` set to event's physical location.
6. Another person: `--attendees email@domain.com` present (never `--guest-email`).
7. Flights the user sends (screenshot, itinerary, forwarded email): don't assume it's his. Unless his name is on it, ask one line first — "Your flight, or are you picking someone up?"
   - **Pickup:** run `Skills/airport-timing/scripts/pickup_time.py --flight … --airport … --arrival "<landing time as shown>" [--checked-bag] [--passenger …]` and then its printed `propose_command`. It computes when the passenger is out, when to leave (predicted traffic), and builds the event and reminder — don't hand-build them. Never ask for anything already on the screenshot (airline, flight number, times, airports). Only ask whether they're checking a bag if the user didn't say, and the passenger's name (optional).
   - **the user's own flight:** itinerary times are local to each airport. Pass each with its own UTC offset (ATL 12:59pm → `2026-09-22T12:59:00-04:00`, DAL 2:05pm → `2026-09-22T14:05:00-05:00`) and `--tz` = the departure airport's zone. Never put both times in one zone without converting.
Fix any ❌ before proceeding. Then send the draft with `Skills/shared/add_calendar_event.py ... --propose`: The user gets it with an Approve button, and the event is created only when he taps it. Never type your own "Approve to proceed?" or "✅ to confirm" — nothing binds to it (the wrapper without `--propose` is blocked from chat). Never execute calendar writes and report completion in one step.
