## Daily Reminder/Check-in Replies in Free Text (not a callback)
Every reminder above that logs to its own dated state file — meal windows, hydration, daily check-ins, movement — can also be answered in plain text instead of a tap. The user replying "had lunch," "logged 16oz," or "did my walk" is just as valid an answer as tapping the matching button, and must be handled the same way.

**2026-09-18 — use the one command: `python3 Skills/<health-skill>/scripts/log_day.py` with one flag per thing he said (`--help` lists them).** It hands each item to the script listed below, so you never call those directly for a typed reply, and its printed ✓ / "NOT logged" lines are your reply. Pass only what he said — `--meal <window> ""` when he didn't name the food; never guess an item (that day an item he never mentioned was logged, and two other check-ins were reported as confirmed when neither script had run). A direct Telegram *reply* to a meal nudge never reaches you — the callback-dispatch plugin logs it by code — so anything you do see is a free-standing message. The per-script list below is reference for what `log_day.py` runs.

**Never just acknowledge it in chat — run the exact script the matching button would have run.** That script is what both logs the entry AND clears/edits the reminder's Telegram buttons via that skill's own state file (`meal_reminder_state.json` / `hydration_nudge_state.json` / `movement_reminder_state.json` / `energy_checkin_state.json`). Replying conversationally without running the script leaves the buttons stuck live and the entry unlogged — diagnosed 2026-09-12 when a text reply to a meal reminder left its buttons on screen because nothing ever called `confirm_meal.py`.

**Never write the report into `MEMORY.md` instead.** Happened twice on 2026-09-13 despite this section already existing — a free-text check-in report got appended as a dated bullet under MEMORY.md's "## Health" section, which nothing reads. (Backstop: the `memory-health-guard` plugin blocks an `edit`/`write` to MEMORY.md that reads like a health-log entry near that section — but do not rely on it; run the correct script directly.)

Map his words to the closest option, reusing the exact commands from the callback table above:
- **Meal window** — what he ate → `nutrition/scripts/confirm_meal.py --date <today> --slot <slot> --action eaten --what "<the food part of his message, word for word>"` ("had something else", no food named → `--action declined`). **Typed replies always use `--what`, never `--choice`** (that is for button taps), and never `log_food.py` — the script stores his words as given and works out the item itself, so don't pick a code, tidy his wording, or write "off-plan". Same command again if he later names or corrects a window that is already logged: it updates that entry. Other things in the same message (a feeling, water) go to their own scripts. Slot = whichever window is currently live — check `meal_reminder_state.json` for today's open entries; ask if genuinely ambiguous which one he means.
- **Readiness score** → `nutrition/scripts/log_energy.py --score <N>` (the 1–10 he gave).
- **Hydration amount** → `hydration/scripts/log_hydration.py --oz <N>`.
- **How he's feeling** — any message like "feeling foggy after lunch" → `<health-skill>/scripts/log_feeling.py --note "<his exact words>"`. His physician reads this quoted: never paraphrase, summarize, tidy, or add to it. If one message has both a check-in and a feeling, run both scripts. Answer with the script's one-line output, nothing more — no advice, no commentary on the feeling.
- **Movement done/skipped** → `hevy-workout/scripts/log_movement.py --date <today> --action <done|skipped>`.

This is structural, not a list to keep manually in sync: any reminder — present or future — that is state-file-tracked and edits its own Telegram message on confirm needs its free-text replies routed through that same script, never answered as plain conversation.
