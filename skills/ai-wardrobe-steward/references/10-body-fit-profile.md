## Body & Fit Profile

Same principle: no mandatory measurement collection, ever. Ask for a measurement or fit preference only when something in front of you actually needs it — most often a fit-critical Shopping Advisor call — never as a standalone step.

1. **Capture units the first time a measurement is actually needed**, not before — ask once (`imperial` or `metric`) so numbers are never ambiguous.
2. **Draft a diff, same discipline as Style Identity.** `set` uses dot-paths for nested fields (`measurements.chest`, `fit_preferences.bottoms.rise`), each value `{value, confidence, importance}` (or `null` to clear). A `set` on an existing path merges rather than replacing wholesale — only include the fields actually changing; whatever's already stored (including evidence and other contexts) survives untouched. `add` on `brand_sizing` — `{"brand": "J.Crew", "category": "shirt", "size": "M", "notes": "true to size", "confidence": 70, "evidence": [{"date": "2026-07-13", "note": "said a Medium fit well"}]}` — matches an existing (brand, category) pair and merges into it rather than duplicating. Write to `profile/pending_body_fit_update.json` with a `review_summary`.
3. **Show the summary and wait for confirmation** — same as Style Identity, never silently overwrite.
4. **On confirmation:** `python3 scripts/confirm_body_fit_update.py` (`--show` first). On rejection: `python3 scripts/cancel_body_fit_update.py`. The confirm script rejects (without writing) any fit-preference value outside `vocab.yaml`'s `fit_preference_scales`, a non-numeric measurement, a context key that isn't a valid occasion tier, or a missing/invalid confidence/importance.
5. **A stale, high-confidence measurement is still worth reconfirming before a fit-critical call.** If `measurements.measured_date` is more than ~12 months old, ask whether anything's changed before leaning on those numbers for a specific purchase.
6. `brand_sizing` only ever grows or gets reinforced via `add` — no `remove` path; a full correction is rare enough to handle as a direct one-off diff.
7. **When a fit preference genuinely varies by occasion** ("I like things relaxed, but I need something more structured for work"), set the default value plus a `contexts` override keyed by the relevant occasion tier — e.g. `{"value": "relaxed", "confidence": 85, "importance": 60, "contexts": {"business-formal": {"value": "classic", "confidence": 70, "importance": 80}}}`. When composing an outfit or evaluating a purchase for a specific occasion, check for a matching context override before falling back to the default.

**Deep calibration is an occasional, optional offer — never a gate.** If confidence across the profile is broadly thin and that's actually limiting a recommendation, it's fine to offer a calibration moment: reviewing the style profile so far, sending 5-10 outfit photos, entering measurements, reviewing brand history — always framed as a real offer with an easy no ("Want to spend a minute improving my recommendations? Totally fine to skip"), never repeated on a schedule. Before offering, check `calibration_last_offered` in `style_profile.yaml` — if it was offered recently and declined or ignored, don't ask again without a real reason (a long gap, or a moment where it would obviously help). Record the offer (confirmed write, same diff mechanism as any other style update) regardless of whether it's accepted, so the next conversation knows not to re-ask immediately.
